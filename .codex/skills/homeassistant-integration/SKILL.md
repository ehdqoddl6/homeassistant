# Home Assistant 기기와 커스텀 컴포넌트 연동

이 저장소의 `AGENTS.md`를 따른다. 아래 파일 경로는 저장소 루트 기준이다.
`docs/environment.md`와 관련 작업 이력을 읽고, 현재 환경에서 확인된 사실부터 사용한다.

## 대상과 호환성 확인

- 제품명·모델, 통합 domain, Home Assistant 버전, 설치 방식, 현재 오류와 원하는 동작을 파악한다.
- 공식 통합인지 커스텀 컴포넌트인지 구분한다. 커스텀 컴포넌트는 실제 upstream URL, 설치 버전 또는 커밋, 설치 경로·방법을 확인한다.
- 현재 upstream 문서·릴리스·관련 이슈를 읽어 지원 장비, 인증 방식, 의존성, 호환 버전을 확인한다. 최신 버전이라는 이유만으로 호환된다고 결론 내리지 않는다.
- 설치·설정 방식은 해당 통합이 지원하는 UI config flow, YAML, HACS 또는 수동 설치 중 실제 환경에 맞게 선택한다. 확인되지 않은 설치 절차는 확정하지 않는다.

## 연동 또는 문제 해결

- 설치, 인증, 통합 로드, 엔티티 생성, 상태 갱신, 제어 중 어느 단계에서 막히는지 나눈다. 관련 로그·설정·코드로 원인을 좁힌 뒤 수정한다.
- 기존 통합의 재설치·삭제나 엔티티 ID 재생성 전에 자동화와 대시보드의 참조 영향을 확인한다.
- 외부 컴포넌트는 upstream과 버전 정보를 먼저 기록한다. 사용자 요청 없이 소스 전체를 저장소에 복사하지 않는다.
- 로컬 코드를 수정할 때만 `config/custom_components/<domain>/` 등 확인된 관리 경로를 사용한다. 기존 `manifest.json`, 의존성과 라이선스를 보존하고 변경 파일·이유를 남긴다.
- 코드 변경은 해당 버전의 개발 문서를 기준으로 검증한다. 이벤트 루프 차단, 연결·인증 실패 처리, 엔티티 식별자, unload 시 자원 해제 등 변경에 직접 관련된 동작을 확인한다.
- 통신 패킷을 분석할 때는 관측값과 추정을 분리한다. 단일 캡처에서 목적지·제어 명령을 단정하거나 추정 패킷을 실제 장비에 보내지 않는다.

## 검증과 기록

- 문서 조사, 로컬 코드 검사·관련 테스트, Home Assistant 로드 확인, 실제 상태·제어 확인을 각각 구분한다.
- 적용 요청이 있으면 백업과 되돌릴 버전·설정, 필요한 재시작 범위를 준비한 뒤 승인된 범위에서 수행한다. 실행 환경에 접근할 수 없으면 적용 안내와 미검증 사항을 남긴다.
- 설치했다고 연결 성공으로 처리하지 않는다. 상태 확인과 제어 확인도 구분하며 해당 기능이 없는 통합에는 요구하지 않는다.
- `docs/templates/change.md`에 upstream 링크·버전, 선택 이유, 변경 파일, 결과, 미해결, 복구 방법을 남긴다. 히스토리 목록과 확인된 환경 정보를 갱신한다.

결과는 연동 상태, 변경 내용, 근거·검증 결과, 남은 작업을 중심으로 전달한다.
인증정보와 개인 식별정보가 포함된 원본 로그·`.storage`·백업은 기록에 복사하지 않는다.

## 필요할 때 확인할 자료

- 대상 통합의 공식 문서 또는 실제 upstream 저장소를 우선한다.
- [Integration manifest](https://developers.home-assistant.io/docs/creating_integration_manifest/): manifest와 의존성 관련 변경 시 확인한다.
- [Home Assistant 개발 문서](https://developers.home-assistant.io/): 직접 코드를 수정할 때 관련 항목만 읽는다.
