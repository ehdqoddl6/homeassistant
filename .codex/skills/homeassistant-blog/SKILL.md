# 기록에 근거한 Home Assistant 구축기

이 저장소의 `AGENTS.md`를 따른다. 아래 파일 경로는 저장소 루트 기준이다.
작업 기록에 담긴 경험을 독자가 따라갈 수 있는 한국어 글로 정리한다.

## 근거 모으기

- `blog/README.md`, 기존 관련 글, `docs/environment.md`, `docs/history/README.md`를 읽는다. 주제에 해당하는 기록·설정 파일·제공된 사진만 추가 확인한다.
- 사용자 확인 내용, 실제 수행 결과, 문서에서 조사한 사실, 아직 검증하지 않은 내용을 구분한다.
- 확인되지 않은 성공 경험·수치·소요 시간·개인적인 계기를 만들어 넣지 않는다. 기록이 부족하면 가능한 범위의 초안을 만들고 필요한 정보는 편집 메모에 남긴다.
- 버전별 설정이나 제품 사양 등 기술 사실은 공식 문서·upstream 자료로 확인하고 출처를 붙인다. 과거 환경을 최신 환경처럼 바꾸지 않는다.

## 글 구성

- `docs/templates/blog.md`를 참고해 `blog/YYYY-MM-DD-주제.md`에 작성한다. 기존 글 수정 요청이면 해당 파일을 갱신한다.
- 필요했던 이유 → 환경과 준비 → 선택과 구성 과정 → 실제 시행착오 → 확인한 결과와 남은 점이 자연스럽게 이어지도록 쓴다. 자료가 없는 절은 생략한다.
- 짧은 문단과 설명적인 소제목을 사용한다. 대화용 호칭인 `오빠`와 연인 말투는 본문에 넣지 않는다. 기존 글의 문체나 사용자 지정 문체를 우선한다.
- YAML·코드는 원본 설정과 맞추고 붙여 넣을 파일·위치, 필요한 사전 조건, 독자가 바꿀 값을 함께 설명한다. 예시 값과 실제 검증된 값을 구분한다.
- 시행착오는 관찰한 증상, 확인한 원인, 시도와 결과의 관계로 설명한다. 원인이 미확정이면 가능성으로 남긴다.
- 본문의 단정은 기록의 검증 수준을 넘지 않는다. 문법 검사만 했다면 실제 동작 성공으로 쓰지 않는다.

## 마무리

- 코드와 버전·기기 정보가 원본 기록과 일치하는지 확인한다. 외부 링크는 실제 참고한 페이지를 사용한다.
- 공개용 코드·이미지·로그에서 토큰, 웹훅 URL, 주소, 개인 위치, 식별정보를 가린다. 원본 비밀값은 글에 복사하지 않는다.
- 부족한 사진은 필요한 장면을 편집 메모에 적는다. 존재하지 않는 스크린샷을 생성한 것처럼 첨부하거나 링크하지 않는다.
- 원본 기록, 작성 상태, 발행일·URL을 메타정보로 남기고 `blog/README.md` 목록에 추가한다. 원본 작업 기록에도 글을 연결한다.
- 초안 작성은 외부 발행을 포함하지 않는다. 발행 요청이 있으면 본문과 발행 대상이 확정된 범위에서 수행하고, 성공 결과를 확인한 뒤 상태와 URL을 갱신한다.

사용자에게 글 경로, 글의 핵심, 추가 확인이 필요한 항목만 간결하게 전달한다.
