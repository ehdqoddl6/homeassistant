# 평일·일요일 브리핑 통합과 주말 07:45 실행

- 작업일: 2026-11-27 (Asia/Seoul)
- 상태: 로컬 통합·정적 검증 완료 / HA 미적용
- 운영 적용: 미적용
- 대상 환경과 버전: Home Assistant UI 자동화 2개(평일 아침 브리핑, 일요일 브리핑). 현재 HA 버전은 이번 작업에서 미확인
- 관련 기록: [새 캘린더 `calendar.yeni` 추가와 데이트 규칙](2026-11-21-briefing-calendar-yeni.md), [아침 브리핑](2026-10-04-morning-briefing.md), [일요일 브리핑](2026-10-04-sunday-briefing.md)

## 목적과 관찰

사용자 요청:

- 평일 아침 브리핑과 일요일 브리핑을 자동화 하나로 합친다.
- 토요일·일요일은 07:45에 실행한다. 기존에는 둘 다 07:40이었다.
- 월요일·일요일은 주식 시장 이야기를 하지 않는다.

기존 상태(2026-11-21 HA 적용본 기준):

- 평일 아침 브리핑: 월~금 07:03:30, 토 07:40. 날씨·일정·환율·미국 시장 전체를 말하고, 일요일 분기 문구가 있었지만 일요일 트리거가 없었다.
- 일요일 브리핑: 일 07:40. 날씨·일정·환율 한 문장·휴일 인사. 일정 조회 실패를 일정 없음과 구분했다.
- 두 자동화는 같은 날씨 센서·캘린더 6개·AI·TTS 설정을 썼다.

선택 이유:

- **월·일에 시장 제외**: 한국 시간 일요일·월요일 아침에는 그 전날 아침 이후 새로 마감한 미국 장이 없다. 토요일 아침은 금요일 장 마감분이라 시장을 유지했다. 월·일에는 시장 센서 값을 instructions에 아예 넣지 않았다. 지시만으로 막는 것보다 AI가 시장 이야기를 할 근거 자체가 없어진다.
- **월·일 환율**: 사용자 요청은 "주식 시장"만 빼는 것이었다. 기존 일요일 브리핑처럼 환율은 한 문장만 말하게 남겼다. 빼려면 `{% else %}` 쪽 환율 문단과 순서 문장만 지우면 된다.
- **요일 판단 위치**: 트리거 ID 대신 instructions 안에서 `now().weekday()`로 판단했다. 수동 실행해도 그날 요일 기준으로 동작한다. 스크립트 변수(`variables`)를 쓰면 HA가 `True`/`False`를 문자열로 넘길 가능성을 따져야 해서, 같은 템플릿 안의 `set`으로 처리했다.
- **기준 원고**: 6일을 실행하던 평일 instructions를 바탕으로 했다. 일요일 브리핑에서는 일정 조회 실패 구분과 "시간대별 예보를 추측하지 마"만 가져왔다. 말투 예시의 `'엔비디아: ...달러'`는 시장이 없는 날에도 들어가는 문단이라 `'환율: ...원'`으로 바꿨다. 종목 문장 예시는 시장 문단 안에 이미 있다.
- **일정 없음**: 평일 방식(일정 부분 생략)을 따랐다. 일요일 단독 브리핑은 "오늘은 등록된 일정이 없어요"라고 말했었다.
- **자동화 위치**: 기존 평일 자동화(`morning-briefing`)를 통합본으로 쓰고 일요일 자동화는 끄도록 했다. 폴더 이름을 바꾸면 기존 기록의 링크가 많이 깨져서 유지했다.

## 운영 반영과 복구

미적용. 적용 순서:

1. HA **설정 → 자동화**에서 **평일 아침 브리핑**을 열고 YAML 편집기에서 [통합본](../../config/automations/morning-briefing/automation.yaml) 전체로 교체해 저장한다. 이름이 `아침 브리핑`으로 바뀐다.
2. **일요일 브리핑** 자동화를 비활성화한다. 한두 주 지켜보고 문제없으면 삭제한다. 켜 두면 일요일에 07:40·07:45 두 번 안내한다.
3. 2026-11-21 이후 HA에서 두 자동화를 따로 고친 적이 있으면 그 부분이 덮어써진다. 교체 전에 HA 쪽 YAML을 복사해 두면 비교할 수 있다.

복구: 아침 브리핑을 [morning-briefing/history/2026-11-27-before-merge.yaml](../../config/automations/morning-briefing/history/2026-11-27-before-merge.yaml)로 되돌리고, 일요일 브리핑을 다시 켠다. 삭제했다면 [sunday-briefing/history/2026-11-27-before-merge.yaml](../../config/automations/sunday-briefing/history/2026-11-27-before-merge.yaml)로 새로 만든다. 두 보관본에는 `new Date()` 데이트 규칙이 없다.

## 후속 (2026-11-27): 말투 부드럽게, 섹터 요약 간단히

사용자 의견: 말투가 너무 딱딱하다. 시장 섹터 요약은 간단하게.

| 위치 | 변경 |
| --- | --- |
| instructions 말투 | "뉴스 앵커처럼 딱딱하게 읽지 말고 옆에서 이야기하듯 부드럽고 다정한 해요체" 지시 추가. `...습니다`·`...하겠습니다` 대신 `...이에요`·`...네요`·`...거든요`. "전일 대비"는 "전날보다"로 말하게 함. 실제 값에 맞을 때만 가벼운 공감 한마디("다행히 비 소식은 없어요" 등) 허용. 2026-11-01에 뺀 개인 호칭·반말은 계속 쓰지 않음 |
| 말투 예시 | 날씨 예시의 "오가겠습니다", 종목 예시의 "내렸습니다"·"기록했어요"를 해요체로 바꿈. 인사 "좋은 아침이에요", 시장 전환 "이번엔 시장 얘기 해볼게요" |
| 섹터 | 여섯 섹터를 순서대로 모두 말하던 규칙을 없앰. 가장 강했던·약했던 섹터만 한두 문장으로, 대부분 같은 방향이면 전체 흐름 한마디 |
| 시장 심리 | 공포지수·10년물 금리를 한두 문장으로 짧게 |
| 마무리·실패 안내 | 출근·주말 인사를 따뜻한 한 문장 예시로. 고정 실패 TTS를 "불러오지 못했어요. 잠시 뒤에 다시 확인해 주세요."로 바꿈 |

섹터 입력 자료(SOXX·XLK·XLF·XLE·XLV·XLY 6개)는 그대로 넘긴다. 가장 강했던·약했던 섹터를 고르려면 전체 값이 필요해서다.

추가 수정(같은 날): 사용자가 "자동화 말투를 자연스럽게 하라는 것"이라고 다시 짚었다. 위 표의 "다정한 해요체", 공감 한마디, "따뜻한" 마무리 예시("푹 쉬면서", "잘 다녀오세요")는 에이전트 대화 말투가 섞인 것이어서 뺐다. 지금 지시는 "사람이 평소에 말하듯 자연스러운 구어체 해요체"이고 호칭·반말·애교·애정 표현·지나치게 다정한 말투를 금지한다. 마무리 인사는 통합 직후 문구("짧은 출근 인사 한 문장", "편안한 주말을 보내라는 짧은 한 문장")로 되돌렸다. 격식체 줄이기, "전날보다", 섹터·시장 심리 간단 요약은 유지했다.

검증: Ruby YAML 파싱 통과, `{%` 48/48·`{{` 66/66. 일반 Jinja2로 월~일 다시 렌더링했고 월·일 시장 단어 0건, 섹터 간단 요약 지시는 화~토에만 들어갔다. 실제 원고가 덜 딱딱하게 들리는지는 미확인.

## 후속 (2026-11-27): 일정 조회 실패도 "일정 없음"으로

사용자 요청: 일정이 조회되지 않으면 그냥 일정이 없다고 말한다.

| 위치 | 변경 |
| --- | --- |
| `schedule_text` | `ns.failed` 추적과 실패 문구("일정 정보를 가져오지 못했습니다", "일부 캘린더의 일정 정보를…")를 없앴다. 일정 줄이 하나도 없으면 원인과 상관없이 `등록된 일정 없음`이다. 일부 캘린더만 응답하면 받은 일정만 나온다 |
| `[오늘 일정]` 기본값 | `default('등록된 일정 없음', true)` |
| instructions 일정 부분 | 조회 실패·일부 실패 안내 두 줄을 지웠다. `등록된 일정 없음`이면 일정 부분을 건너뛰지 않고 "오늘은 등록된 일정이 없어요"처럼 한 문장으로 말한다 |

이렇게 바꾸면 캘린더 조회가 실패한 날에는 실제 일정이 있어도 "일정이 없다"고 안내한다. 사용자가 이 동작을 원했다. 위 "선택 이유"의 조회 실패 구분과 "일정 없음은 생략"은 이 후속으로 바뀌었다.

검증: Ruby YAML 파싱 통과, `{%` 38/38·`{{` 65/65. 일반 Jinja2로 `schedule_text`를 렌더링했다. 정상 응답에 일정 없음, 전체 실패(`{}`), 응답 변수 없음은 모두 `등록된 일정 없음`이었다. 일부 캘린더만 응답하면 `- 회의 (10:00)`만 나왔고 실패 문구는 없었다. `new Date()` 데이트 줄은 그대로였다. 월·일 instructions 렌더링에서 시장 단어 0건도 유지됐다.

## 미해결과 다음 작업

- HA에 적용한 뒤 토·일 07:45 실행, 일요일 중복 안내 없음 확인.
- 실제 원고·음성이 덜 딱딱한지, 섹터가 한두 문장으로 줄었는지 확인.
- 월요일·일요일 원고에 지수·섹터·종목 이야기가 빠지고 환율 한 문장만 나오는지 확인.
- 토요일 원고가 시장 이야기 뒤에 출근 인사가 아니라 주말 인사로 끝나는지 확인.
- 월·일 환율도 빼고 싶은지 사용자 확인 필요(현재는 한 문장 유지).
- `new Date()` 데이트 일정이 장소와 함께 낭독되는지 확인([2026-11-21 기록](2026-11-21-briefing-calendar-yeni.md)의 미해결 항목).
