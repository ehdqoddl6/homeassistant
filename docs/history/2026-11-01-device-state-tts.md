# 제습기·선풍기·환풍기 상태 알림 통합

- 작업일: 2026-11-01 (Asia/Seoul)
- 상태: 로컬 작성·정적 검증 완료
- 운영 적용: 미적용
- 대상 환경과 버전: [환경 기록](../environment.md)의 Home Assistant OS / Core 2026.9.3 (2026-10-04 사용자 제공 화면 기준). 현재 서버 상태는 미확인.

## 목적과 관찰

사용자가 UI에서 쓰는 제습기 켜짐·꺼짐 자동화 2개와 안방 선풍기 꺼짐 자동화 1개의 YAML을 제공하고, 하나로 합칠 수 있는지 요청했다. 확인된 엔티티는 `switch.jeseubgi`, `switch.fan_m`이며 실제 상태와 동작은 조회하지 않았다.

## 변경과 선택 이유

- [통합 자동화](../../config/automations/device-state-tts/automation.yaml)에 상태 트리거 세 개를 넣고, 트리거 ID로 대기 시간과 안내 문구를 구분했다. 켜짐 4초와 꺼짐 1초, TTS 대상·음성·캐시 설정은 사용자 제공 YAML을 따른다.
- 세 개의 독립 자동화에서 하나로 합칠 때 `single` 모드는 먼저 시작한 대기 중 다음 상태 변화를 버릴 수 있다. `parallel`로 각각 대기하되, 대기가 끝난 시점의 기기 상태를 다시 확인해 이미 바뀐 상태의 안내는 생략한다.
- 안방 선풍기의 반말 안내는 이전에 요청한 중립적인 존댓말로 바꿨다.
- [자동화 폴더 README](../../config/automations/device-state-tts/README.md)에 기존 자동화 비활성화, 검증 상태와 복구 방법을 적었다.

UI의 **새 단일 자동화 YAML 편집기**에 넣는 형태이며, 저장소에서 읽는 상위 include는 없다. 적용하려면 기존 자동화 세 개를 비활성화해야 중복 음성을 피할 수 있다.

## 운영 반영과 복구

운영 서버에는 적용하지 않았다. 적용 시 새 자동화 1개를 등록하고 기존 제습기 켜짐·꺼짐, 안방 선풍기 꺼짐 자동화 3개를 비활성화한다. 복구 시 통합 자동화를 비활성화하고 기존 세 개를 다시 활성화한다. 원본 YAML은 사용자 메시지에 있다.

## 미해결과 다음 작업

각 엔티티의 실제 상태 변경, 4초·1초 대기, 짧은 간격의 상태 반전, TTS 청취를 운영 환경에서 확인해야 한다. 자동화의 동작만 수동 실행하면 `trigger` 데이터가 없어 분기 템플릿을 검증할 수 없다.

## 같은 날 후속: 환풍기 켜짐·꺼짐 추가

사용자가 `fan.kocom_ventilation_0_0`의 꺼짐 자동화 YAML을 제공하고 켜짐·꺼짐 모두 추가해 달라고 요청했다. [통합 자동화](../../config/automations/device-state-tts/automation.yaml)에 `ventilation_on`, `ventilation_off` 상태 트리거를 추가했다. 꺼짐은 제공된 1초 대기와 “환기를 종료합니다.”를 유지했다. 켜짐은 제습기 켜짐과 같은 4초 대기, “환기를 시작합니다.”로 구성했다. 두 경우 모두 대기 후 현재 상태를 다시 확인한다.

작업 시작 시 로컬 YAML의 선풍기 문구가 앞서 작성한 문구에서 “안방 화장실 선풍기가 꺼졌습니다.”로 바뀌어 있었다. 이 사용자 변경은 유지했다. 현재 통합 자동화는 상태 트리거 다섯 개를 가진다. 운영 적용 시 기존 환풍기 꺼짐 자동화도 비활성화해야 중복 음성을 피할 수 있다. 환풍기 켜짐 자동화가 별도로 있는지는 미확인이다.

확장 후 YAML 파싱·중복 키·트리거 ID·대기 시간·TTS 구조·문서 링크를 정적으로 확인했다. Home Assistant 구성 검사와 실제 환풍기 상태 변경·음성 청취는 수행하지 않았다. 환풍기 추가만 되돌릴 때는 통합 YAML의 `ventilation_on`·`ventilation_off` 트리거와 두 안내 분기를 제거하고, 기존 환풍기 꺼짐 자동화를 다시 활성화한다.
