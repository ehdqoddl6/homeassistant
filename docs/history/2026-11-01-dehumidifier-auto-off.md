# 제습기 2시간 후 자동 끄기 보관

- 작업일: 2026-11-01 (Asia/Seoul)
- 상태: 기존 자동화 사용 중 (사용자 확인), YAML 로컬 보관·정적 검증 완료
- 운영 적용: 사용자 확인 / 에이전트 미적용
- 대상 환경과 버전: [환경 기록](../environment.md)의 Home Assistant OS / Core 2026.9.3 (2026-10-04 사용자 제공 화면 기준). 현재 서버 상태는 미확인.

## 목적과 관찰

사용자가 제습기가 켜진 후 2시간 뒤 자동으로 끄는 YAML을 제공하고, 기존 기기 상태 음성 알림에 추가할 수 있는지 물었다. 긴 대기와 기기 제어를 음성 알림의 짧은 대기·TTS와 분리해 별도 자동화로 보관하기로 했다. 후속 확인에서 사용자는 이 자동화가 이미 운영 중이라고 알려주었다.

## 변경과 선택 이유

- [자동 끄기 YAML](../../config/automations/dehumidifier-auto-off/automation.yaml)을 사용자 제공 내용에 맞춰 저장했다. `switch.jeseubgi`가 `on`으로 바뀌면 2시간 기다리고, 여전히 `on`일 때 `switch.turn_off`를 호출한다.
- `mode: restart`를 유지했다. 대기 중 껐다가 다시 켜면 새 `on` 트리거가 대기를 처음부터 시작한다. 꺼진 상태라면 2시간 뒤 조건에서 중단된다.
- [기기 상태 TTS 자동화](../../config/automations/device-state-tts/automation.yaml)는 변경하지 않았다. 두 자동화가 운영 적용돼 있다면 자동 끄기로 인한 `off` 상태 전환이 TTS 꺼짐 안내를 유발할 수 있다.

로컬 보관본은 UI의 단일 자동화 YAML 편집기에 넣을 수 있는 형태다. 실제 운영 서버의 관리 방식과 저장소에서 읽는 상위 include는 확인되지 않았다.

## 운영 반영과 복구

에이전트는 서버에 적용하지 않았다. 사용자가 동일 자동화가 이미 운영 중이라고 확인했으므로 새 자동화를 중복 생성하지 않는다. 이번 로컬 보관 작업은 운영 복구가 필요하지 않다. 향후 운영 설정을 수정할 때는 서버의 현재 설정과 백업을 확인한다. 상태 TTS 자동화는 별도로 유지한다.

## 미해결과 다음 작업

실제 제습기 엔티티 상태와 두 시간 뒤 동작은 미확인이다. Home Assistant 재시작·자동화 재로드·자동화 비활성화 시 진행 중인 2시간 대기는 사라진다. 재시작 뒤에도 남은 시간을 유지해야 한다면 지속형 타이머 도우미와 별도 종료 트리거 구성이 필요하다.

초기 기록에는 운영 미적용으로 적었으나, 사용자가 “이미 실행중이던거였는데 동기화가 안됐나보다”라고 알려 기존 자동화가 운영 중임을 확인했다. 로컬 파일 작성이나 에이전트의 서버 적용을 뜻하지 않으며, 실제 2시간 후 자동 꺼짐 성공은 아직 확인하지 않았다.
