# 지하철 안내 말투 개선과 도착 예정 시각 계산

- 작업일: 2026-10-10 (Asia/Seoul)
- 상태: 로컬 수정·Jinja 대역 검증 완료 / 실제 원고·음성 확인 대기
- 운영 적용: 미적용
- 대상 환경: 기록상 Core 2026.9.3 / Home Assistant OS. 현재 서버 버전·시간대·센서 상태는 조회하지 않음.
- 관련 파일: [지하철 스크립트](../../config/scripts/subway-briefing/README.md)
- 이전 기록: [지하철 도착 음성 안내 스크립트 작성](2026-10-09-subway-briefing-script.md)

## 목적과 관찰

사용자가 지하철 안내 말투가 부자연스럽다고 알려주고 현재 시각에 남은 시간을 더한 도착 시각도 함께 안내하도록 요청했다.
구체적인 실제 원고나 음성은 전달받지 않았으므로, 저장소 프롬프트의 안내 방송 역할과 반복되는 기준 설명을 줄이는 방향으로 수정했다.
도착 시각은 평내호평역에 열차가 도착할 예정 시각으로 해석했다.

## 변경과 선택 이유

- `config/scripts/subway-briefing/script.example.yaml`: `description`과 AI Task의 `instructions`만 변경한다.
- `config/scripts/subway-briefing/history/2026-10-10-before-arrival-time.example.yaml`: 수정 전 저장소 YAML을 그대로 보관한다.
- 해당 스크립트 README, 이전 작성 기록과 전체 히스토리에 이번 변경·적용·복구 방법을 연결한다.

문체를 옆에서 알려주는 듯한 부드러운 해요체로 바꾸고, 열차별 행선지·남은 시간·도착 예정 시각을 한 문장으로 연결하도록 요청한다.
같은 역 이름, 격식 있는 방송 문구와 '조회 기준' 설명이 반복되지 않게 하며, 예상 시각은 자연스럽게 '~쯤'으로 표현한다.
같은 날 사용자가 '실제와 다를 수 있다'는 마무리 문구도 빼 달라고 요청해, 행선지·남은 시간·도착 시각만 말하고 끝내도록 지시를 수정했다. 단서·주의 문구·재확인 권유·끝인사를 금지하며 시간 계산과 누락 처리는 유지한다.
이어 '조회된 기준으로 알려드립니다'라는 도입도 빼 달라는 요청에 따라, 조회 기준 설명 없이 첫 열차의 행선지와 시간부터 바로 말하도록 명시했다.
후속 요청으로 도입은 “평내호평역 실시간 지하철 정보를 알려드립니다.” 한 문장으로 정했다. 도착 정보가 있을 때 이 문장으로 시작하고, 열차 설명은 부드러운 해요체로 이어간다. 조회 기준 설명과 마지막 단서 문구를 빼는 지시는 유지한다.

각 AI 호출의 프롬프트 렌더링에서 `now()`를 한 번 읽는다.
검증된 `N분 N초`의 분·초를 추출하고 `reference_time + timedelta(minutes=minutes, seconds=seconds)`로 계산한다.
계산 결과의 날짜·시각과 음성용 오전/오후 시·분 표현을 함께 전달해 LLM이 시간 덧셈을 수행하지 않도록 한다.
자정을 넘으면 `내일`, 이틀 이상 뒤면 월·일을 포함한다. 음성에서는 초를 생략하고 계산 결과의 시·분을 사용한다.
현재 09:15:00, 남은 시간 3분 20초의 합성 입력은 09:18:20, 음성용 표현은 `오전 9시 18분쯤`이 된다.

기존 센서·AI·TTS 엔티티, `Leda`, 최대 3회 생성·응답 검사·실패 안내·`mode: single`을 유지한다.
센서 자체의 계산과 서버 설정은 변경하지 않으며 UI 단일 스크립트 구조와 상위 include 없음도 유지한다.

| --- | --- | --- |
| YAML·기존 실행 흐름 | Ruby Psych, 구조 및 수정 전후 비교 | 통과: 중복 키 없음, 설명·프롬프트 외 실행 흐름 동일, 보관본은 수정 전 Git HEAD와 바이트 일치 |

| 도착 시각 | 고정된 현재 시각과 합성 센서 값 | 통과: 일반·분/시간 경계·정오·자정·월말·연말·윤일·장시간·시간대 포함 12가지. 시도당 `now()` 1회 확인 |
| 잘못된 입력·재시도 | 누락·음수·초 범위 오류 및 두 시점 비교 | 통과: 잘못된 입력 5가지에서 도착 시각 없음. 현재 시각 30초 경과·남은 시간 30초 감소 시 같은 도착 시각 유지 |
| 문서·공백 | 상대 링크 검사와 `git diff --check` | 통과: 변경·추가 파일 6개 공백 검사, 문서 상대 링크 23개 확인 |
| Home Assistant 구성·실행, AI 원고와 TTS | 서버 및 장치 미접속 | 미실행. Jinja 대역 검증은 HA 런타임이나 실제 출력 검증이 아님 |

공식 `now`·`timedelta` 문서와 Core 2026.9.3 템플릿 환경·DateTimeExtension 소스를 확인했다.
도입·마무리 문구 수정 후 YAML 파싱과 공백 검사를 수행하고, 수정 전후 비교로 프롬프트 문장만 바뀌었으며 모든 Jinja 표현식과 실행 흐름이 보존됐음을 확인했다.
공식 소스 다운로드의 첫 시도는 샌드박스 DNS 오류로 실패했으며 승인된 네트워크 접근으로 다시 조회했다.

## 운영 반영과 복구

기존 스크립트 YAML의 `ai_task.generate_data.data.instructions`를 수정본으로 교체한다. 새 시간 계산도 이 블록 안에 있다.
최상위 `description`도 수정할 수 있다. 전체 파일을 교체할 때는 서버에서 바꾼 실제 센서 ID를 유지한다.
Home Assistant의 `now()`는 서버에 설정된 시간대를 사용하므로 한국 시각 안내에는 `Asia/Seoul` 설정을 확인한다.
이번 수정본의 서버 저장·재시작·스크립트 실행·음성 재생은 수행하지 않았다.
되돌리려면 보관본의 `instructions`와 `description`을 복원한다.

## 미해결과 다음 작업

- 실제 AI 원고가 자연스러운 해요체로 나오는지, 남은 시간과 시각을 빠짐없이 전달하는지와 TTS 발음·억양.
- 서버 시간대, 센서 실제 ID·상태, 원본 센서의 누락·시간대 처리.
- 계산은 현재 시각과 센서 저장값의 합이다. 센서 갱신 이후 경과 시간이나 원본 조회 실패로 남은 오래된 값을 보정하지 않는다.
- LLM·TTS 생성 지연 동안 시간이 흐르므로 재생 순간의 정확한 카운트다운은 보장하지 않는다.
