# 세탁기 완료 전·완료 알림 통합

- 작업일: 2026-11-01 (Asia/Seoul)
- 상태: 로컬 수정·정적 검증 완료
- 운영 적용: 미적용
- 대상 환경과 버전: [환경 기록](../environment.md)의 Home Assistant OS / Core 2026.9.3 (2026-10-04 사용자 제공 화면 기준). 현재 서버 상태는 미확인.
- 관련 기록: [기존 10분 전 알림](2026-10-04-lg-washer-tts.md)

## 목적과 관찰

기존 세탁 완료 10분 전 음성 알림에 30분·20분 전 안내를 추가하고, 세 사전 알림을 하나의 자동화에서 관리했다. 기존 10분 전 알림은 사용자가 테스트 성공을 보고했다. 이 작업의 첫 단계에서는 완료 시점 알림을 별도 자동화로 보관했다. 같은 날 후속 요청으로 완료 알림도 통합했다.

## 변경과 선택 이유

- [통합 자동화](../../config/automations/lg-washer-tts/automation.yaml): 첫 단계에서 기존 10분 전 파일 이름을 일반화하고, 같은 `sensor.setaggi_remaining_time`을 기준으로 `-00:30:00`, `-00:20:00`, `-00:10:00` 세 시간 트리거를 설정했다. 각 트리거에 분 수를 `id`로 넣어 TTS 문구에 사용한다.
- 첫 단계에서는 [완료 자동화 보관본](../../config/automations/lg-washer-tts/history/2026-11-01-before-merge-completed.yaml)을 변경하지 않았다. 사전 알림과 완료 이벤트는 발동 기준이 다르며, 완료 이벤트 종류는 아직 확인되지 않았다.
- 자동화 폴더 README와 전체 자동화 목록을 현재 구성에 맞게 갱신했다.

UI의 **기존 10분 전 자동화 한 개**를 새 YAML로 교체해야 한다. 새 자동화를 추가한 채 기존 자동화를 켜 두면 10분 전 알림이 중복된다. 저장소의 YAML을 읽는 상위 include는 확인되지 않았다. 후속 통합 적용 시에는 기존 완료 자동화도 비활성화해야 한다.

## 운영 반영과 복구

운영 서버에는 적용하지 않았다. 첫 단계의 적용 계획은 기존 10분 전 자동화를 교체하고 완료 알림은 유지하는 것이었다. 후속 통합을 적용할 때는 기존 10분 전 자동화의 UI YAML을 [통합본](../../config/automations/lg-washer-tts/automation.yaml)으로 교체하고 기존 완료 자동화를 비활성화한다. 복구 시 Git의 작업 전 `before-complete-10min.yaml` 내용으로 10분 전 자동화를 되돌리고, 보관한 완료 자동화를 다시 활성화한다.

## 미해결과 다음 작업

30분·20분·10분 전 트리거와 TTS 출력은 실제 세탁 시 확인해야 한다. 센서의 예정 시각이 바뀌면 이미 지난 오프셋은 놓치거나, 늦춰진 시각에 따라 같은 분 수 알림이 다시 울릴 수 있다. `mode: single`은 세탁 1회당 한 번만 알린다는 보장이 아니다.

## 같은 날 후속: 완료 알림 통합

사용자가 완료 알림도 하나로 묶을 수 있는지 요청했고, 세탁기는 한 대라고 확인했다. 별도로 보관하던 완료 자동화의 `event.setaggi_notification` 상태 트리거를 [통합 자동화](../../config/automations/lg-washer-tts/automation.yaml)의 네 번째 트리거로 추가했다. `id: complete`일 때는 기존의 “세탁을 종료합니다”를 읽고, 30·20·10분 트리거일 때는 해당 분 수를 읽는다. TTS 대상·음성·캐시·실행 모드는 기존 설정을 보존했다. 원래 완료 YAML은 [보관본](../../config/automations/lg-washer-tts/history/2026-11-01-before-merge-completed.yaml)으로 이동했다.

한 대의 세탁기에서 나오는 이벤트라도 완료 외 알림이 같은 이벤트 엔티티를 갱신하면 기존 완료 자동화와 마찬가지로 완료 안내가 울릴 수 있다. 이벤트 종류와 실제 상태는 확인하지 못해 현재는 사용자 제공 트리거를 그대로 유지했다. 통합 YAML의 네 트리거·분기·중복 키·링크를 정적으로 검사했다. 서버 구성 검사와 실제 세탁·음성 검증은 수행하지 않았다.
