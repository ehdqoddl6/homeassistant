# 날씨 스크립트 기상캐스터 문체 변경

- 작업일: 2026-10-09 (Asia/Seoul)
- 상태: 로컬 수정·정적 검증 완료 / 실제 원고·음성 확인 대기
- 운영 적용: 미적용
- 대상 환경: 환경 기록상 Core 2026.9.3 / Home Assistant OS. 현재 서버 상태는 조회하지 않음.
- 관련 파일: [날씨 스크립트](../../config/scripts/weather-briefing/README.md)
- 이전 기록: [날씨 음성 안내 스크립트 작성](2026-10-08-weather-briefing-script.md)

## 목적과 근거

사용자가 반말 안내 스크립트를 제시하고 기상캐스터가 날씨를 알려주는 것처럼 프롬프트를 바꾸도록 요청했다.
AI Task의 `instructions`를 기상캐스터 역할과 방송체 존댓말로 수정했다.
사용자 제공 YAML은 저장소 버전과 프롬프트 도입부 및 줄바꿈이 달랐으며, 센서 입력과 실행 구조는 같은 형태다.

## 변경과 선택 이유

- `config/scripts/weather-briefing/script.yaml`: `instructions`만 변경했다. 현재 날씨의 특징 → 기온·강수·습도·먼지 → 외출 참고사항 순서로 이어지는 차분한 방송 원고를 요청한다.
- `config/scripts/weather-briefing/history/2026-10-09-before-weathercaster.yaml`: 수정 전 저장소 파일을 그대로 보관했다. 사용자 제공 YAML 원문을 보관한 파일은 아니다.
- 스크립트 README와 이전·전체 히스토리에 새 작업을 연결했다.

개인적인 호칭을 쓰지 않고 숫자를 나열하는 대신 완성된 문장으로 연결한다.
센서 값과 Jinja 입력은 유지하고, 시간대별 예보·특보·다른 지역 날씨나 관측 시각을 추측하지 않도록 했다.
누락 안내도 존댓말로 바꾸었다. AI 생성 실패 시 사용하는 고정 `message`는 프롬프트 외 설정이므로 유지했다.
TTS 음성 `Leda`, 스피커, 재시도, 응답 검사와 `mode`는 변경하지 않았다.

## 검증

| 확인 항목 | 수행 방법 | 결과 |
| --- | --- | --- |
| YAML 문법·중복 키 | Ruby Psych | 통과: 수정본·보관본 2개 파싱, 중복 키 없음 |
| 수정 범위·입력 보존 | 수정 전후 파싱 결과 및 Jinja 표현식 비교 | 통과: `instructions`만 변경, Jinja 표현식 16개 유지, 보관본과 수정 전 Git 파일의 바이트 일치 |
| 문서 링크·공백 | Python 상대 링크·공백 검사, `git diff --check` | 통과: 로컬 링크 19개, 변경·추가 파일 6개 공백 검사 |
| Home Assistant 구성 검사·Jinja 렌더링 | 실행 환경 미연결 | 미실행 |
| 실제 AI 원고·TTS 음성 | AI 호출·스피커 재생 미수행 | 미실행 |

프롬프트 변경은 원고의 문체를 지시한다. 실제 기상캐스터 같은 발성·억양이 구현됐다는 청취 검증은 하지 않았다.

## 운영 반영과 복구

로컬 파일만 변경했다. 적용할 때는 기존 스크립트 YAML의 `instructions` 값을 교체한다. 상위 include 추가는 없다.
되돌릴 때는 보관한 수정 전 YAML의 `instructions`를 복원한다.
프롬프트 수정 당시에는 서버 저장·재시작·스크립트 실행 및 Git 커밋·푸시를 수행하지 않았다.
이후 사용자 요청에 따라 `[feature] 날씨 안내를 기상캐스터 문체로 변경` 메시지의 별도 커밋으로 게시를 진행한다. Git 게시는 Home Assistant 운영 적용과 별개다.

## 미확인 사항과 다음 작업

실제 생성 원고가 방송체·다섯~일곱 문장·자료 범위를 지키는지와 `Leda` 음성을 확인해야 한다.
최대 재시도 실패 시 고정 TTS 안내까지 존댓말로 맞추려면 해당 `message`도 별도로 수정해야 한다.
