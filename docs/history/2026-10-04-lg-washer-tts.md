# 자동화 폴더 구성과 세탁기 TTS 알림 보관

- 작업일: 2026-10-04 (Asia/Seoul)
- 상태: 로컬 기록·검증 완료 / 사전 알림 테스트 성공 (사용자 확인)
- 운영 적용: 사용자 제공 예제 사용·테스트 성공 확인 / 에이전트 미적용
- 대상 환경과 버전: Home Assistant 버전·설치 방식·LG 통합 버전 미확인
- 관련 파일: [자동화 폴더](../../config/automations/lg-washer-tts/README.md)

## 목적과 관찰

사용자는 기존 LG 세탁기 완료 TTS 자동화를 제공하고, 완료 10분 전에도 알림을 받고 싶다고 요청했다.
이어서 자동화 작업 시 폴더를 만들고 히스토리를 남겨 달라고 요청했다.

사용자 제공 YAML에서 알림 이벤트, TTS 엔티티, 출력 대상과 음성 옵션은 확인했다.
초기 보관 시점에는 남은 시간 엔티티 ID·값·속성과 Home Assistant 버전을 확인하지 못했다. 같은 날 설정 사용에 대한 후속 확인은 아래에 남겼다.
제공된 YAML이나 로컬 파일만으로 실제 기기 동작·운영 적용 여부를 확인할 수는 없다.

## 변경과 선택 이유

- `AGENTS.md`: 자동화별 폴더와 README, 날짜별 기록 링크, 예제 파일 구분 규칙을 추가했다.
- `README.md`, `config/README.md`, `config/automations/README.md`: 자동화 보관 위치와 관리 방식을 연결했다.
- `config/automations/lg-washer-tts/README.md`: 목적, 파일 상태, 사용자 제공 엔티티와 미확인 항목, 적용 방법, 히스토리를 정리했다.
- `config/automations/lg-washer-tts/completed.yaml`: 사용자 제공 완료 알림을 변경 없이 보관했다.
- `config/automations/lg-washer-tts/before-complete-10min.example.yaml`: 앞서 안내한 완료 예정 시각 기준 10분 전 알림 예제를 보관했다.
- `docs/history/README.md`: 이 기록을 연결했다.

자동화별 폴더에서 설정과 이력을 찾을 수 있도록 하고, 날짜별 기록 원문은 기존 `docs/history/`에 유지했다.
같은 기록을 중복 작성하지 않고 자동화 폴더와 전체 목록에서 연결한다.

공식 LG ThinQ의 Home Assistant 2026.9.4 구현에서 세탁기 남은 시간 센서가 timestamp 형식임을 확인했고, 공식 시간 트리거 문서의 음수 offset 방식을 참고했다.
이는 사용자의 설치 버전이나 실제 센서를 확인했다는 뜻이 아니다.
예시 센서 ID가 포함된 파일은 `.example.yaml`로 구분했다.

두 YAML은 UI의 단일 자동화 편집기에 넣는 형태이며, 저장소에 로드용 상위 include는 없다.
기존 완료 알림을 보관하고 사전 알림을 별도 자동화로 추가하는 구성이다.

## 검증

| 확인 항목 | 수행 방법 / 명령 | 결과와 근거 |
| --- | --- | --- |
| YAML 문법·중복 키·구조 | Ruby 표준 Psych 파서와 매핑·키 검사 | 통과: 2개 YAML, 중복 키 없음, 단일 자동화 매핑과 트리거·액션 목록 확인 |
| 문서 링크 | Python 표준 라이브러리로 변경 문서의 상대 경로 확인 | 통과: 문서 7개 내 로컬 링크 24개 대상 존재 |
| 변경 내용 공백 검사 | `git diff --check` | 통과 |
| Home Assistant 구성 검사 | 실행 환경 미연결 | 미실행 |
| 에이전트의 실제 세탁·TTS 시나리오 | 서버·기기 접근 및 제어 미수행 | 미실행 |
| 사용자 사전 알림 테스트 | 사용자 대화 확인 | 성공 보고. 실제 시간 트리거 검증인지 액션 수동 실행인지는 미확인 |

로컬 파싱이나 문서 검증을 Home Assistant 구성 검사 또는 실기기 검증으로 취급하지 않는다.
첫 YAML 파싱 시도는 Python 환경의 `PyYAML` 미설치로 `ModuleNotFoundError`가 발생했다.
추가 설치 없이 Ruby 표준 Psych 파서로 전환해 검증했다.

## 운영 반영과 복구

에이전트는 로컬 파일만 생성·수정했다. 서버 적용, 자동화 재로드, Home Assistant 재시작, 기기 제어는 수행하지 않았다.
따라서 에이전트 작업으로 인한 운영 복구는 필요하지 않다.
이후 사용자가 자신의 환경에서 10분 전 알림 테스트 성공을 보고하고, 안내한 예제를 사용했다고 확인했다.
복구하려면 새로 추가한 10분 전 자동화만 비활성화하고 기존 완료 알림을 유지한다.

## 미해결과 다음 작업

- 제공한 YAML 사용은 사용자에게 확인했다. 엔티티의 실시간 값·속성과 설치 버전은 별도로 조회하지 않았다.
- 사용자 테스트 성공은 확인했다. 예정 시각 변경·취소·일시정지와 완료 알림까지 검증했는지는 미확인이다. 현 예제는 예정 시각 변경에 따른 재알림이나 시각 경과에 따른 누락을 방지하지 않는다.
- 기존 완료 자동화는 모든 알림 상태 변경에 반응한다. 실제 `event_type`을 확인한 뒤 완료 알림만 처리할 필요가 있는지 판단한다.

## 같은 날 후속 확인

초기 기록 시점에는 사용자 환경 테스트 결과가 없었다.
이후 사용자가 “10분전 알람 테스트성공했어”라고 알려 사전 알림 상태를 **테스트 성공 (사용자 확인)**으로 갱신했다.
당시 실제 엔티티 ID와 최종 적용 YAML은 미확인이라 로컬 파일의 `.example.yaml` 구분을 유지했다.

추가로 사용자가 “예제로 준거 맞아”라고 확인했다.
이에 제공한 YAML을 사용 중인 설정으로 기록하고, 파일을 `before-complete-10min.yaml`로 바꿨다.
예제 안내 주석만 정리했으며 트리거·엔티티 ID·TTS 설정은 변경하지 않았다.
