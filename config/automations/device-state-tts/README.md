# 기기 상태 변경 TTS 알림

사용자가 제공한 제습기 켜짐·꺼짐, 안방 선풍기 꺼짐, 환풍기 꺼짐 설정을 바탕으로 환풍기 켜짐까지 하나로 합친 UI 자동화 YAML이다.

## 파일과 적용

- [automation.yaml](automation.yaml): UI의 **단일 자동화 YAML 편집기**에 넣는 매핑이다. 저장소에서 읽는 상위 include는 확인되지 않았다.
- 운영 적용 시 새 통합 자동화 1개를 저장하고, 기존 제습기 켜짐·꺼짐, 안방 선풍기 꺼짐, 환풍기 꺼짐 자동화를 비활성화한다. 환풍기 켜짐 자동화가 별도로 있다면 그것도 비활성화한다. 함께 켜 두면 음성 알림이 중복된다.
- 현재는 로컬 파일만 작성했다. 서버에 적용하거나 기기를 제어하지 않았다.

## 확인된 입력과 동작

| 항목 | 근거와 용도 |
| --- | --- |
| `switch.jeseubgi` | 사용자 제공 제습기 켜짐·꺼짐 트리거 |
| `switch.fan_m` | 사용자 제공 안방 선풍기 꺼짐 트리거 |
| `fan.kocom_ventilation_0_0` | 사용자 제공 환풍기 꺼짐 트리거. 켜짐은 같은 엔티티의 `on` 상태를 사용 |
| `tts.google_ai_tts` → `media_player.geosil`, `Leda` | 사용자 제공 TTS 설정 |

- 제습기·환풍기 켜짐은 4초, 제습기·선풍기·환풍기 꺼짐은 1초 뒤 안내한다. 환풍기 켜짐의 4초는 제습기 켜짐 패턴에 맞춰 정한 값이며, 제공된 환풍기 꺼짐 1초는 유지했다.
- 대기 후 해당 기기가 여전히 트리거 상태일 때만 말한다. 그사이 상태가 바뀌면 이전 상태 안내는 생략한다.
- 서로 다른 기기의 대기는 `parallel` 모드에서 독립적으로 실행한다. `single`로 합치면 한 기기의 대기 중 다른 기기의 알림을 놓칠 수 있다.
- 선풍기 안내는 현재 로컬 YAML의 “안방 화장실 선풍기가 꺼졌습니다.”를 유지했다.
- 자동화의 **동작 실행** 버튼은 `trigger` 데이터를 제공하지 않으므로 이 파일의 템플릿 검증에 적합하지 않다. 실제 상태 변경이나 트리거 시뮬레이션으로 확인한다.

## 검증과 운영 상태

- 로컬 YAML 문법·중복 키·트리거 ID·대기 시간·TTS 구조·문서 링크를 정적으로 검사했다.
- Home Assistant 구성 검사, 실제 제습기·선풍기·환풍기 상태 변경, TTS 청취: 미실행.
- 운영 적용: 미적용.
- 복구: 통합 자동화를 비활성화하고 기존 제습기·선풍기·환풍기 자동화를 다시 활성화한다. 제공된 원본 YAML은 사용자 메시지에 있다.
