# 제습기 2시간 후 자동 끄기

사용자가 이미 Home Assistant에서 사용 중이라고 확인한 제습기 자동 끄기 YAML을 로컬에 보관한다. 제습기 상태 TTS 알림과 실행 시간이 달라 별도 자동화로 관리한다.

## 파일과 적용

- [automation.yaml](automation.yaml): 사용자가 제공한 기존 운영 자동화의 로컬 보관본이다. UI의 단일 자동화 YAML 편집기에 넣을 수 있는 매핑 형태지만 실제 서버의 관리 방식은 미확인이다. 저장소에서 읽는 상위 include도 확인되지 않았다.
- 이미 운영 중인 자동화이므로 새 자동화를 중복 생성하지 않는다.
- 저장소에는 로컬 파일만 작성했다. 에이전트의 서버 적용·기기 제어는 수행하지 않았다.

## 입력과 동작

| 항목 | 확인 상태 / 근거 |
| --- | --- |
| `switch.jeseubgi` | 사용자 제공 YAML의 제습기 스위치. 실제 상태는 미조회 |
| 동작 | `on` 전환 후 2시간 대기, 여전히 `on`이면 `switch.turn_off` 호출 |
| 실행 모드 | 사용자 제공 `restart` 유지. 대기 중 다시 `on` 트리거가 오면 2시간을 새로 센다 |

제습기를 중간에 끄면 2시간 뒤 상태 조건에서 중단된다. 그 사이 다시 켜면 새 `on` 트리거가 이전 대기를 취소하고 새로 시작한다. Home Assistant 재시작·자동화 재로드 중에는 대기가 사라지므로, 그 뒤 계속 켜져 있어도 자동으로 이어서 끄지는 않는다.

별도의 [상태 TTS 자동화](../device-state-tts/automation.yaml)가 운영 적용돼 있다면, 이 자동화가 제습기를 끌 때 꺼짐 음성 안내가 발생할 수 있다.

## 검증과 운영 상태

- 로컬 YAML 파싱·중복 키·동작 구조·문서 링크·공백 검사: 통과.
- Home Assistant 구성 검사, 실제 2시간 대기·제습기 끄기·TTS 연계: 에이전트 미실행. 사용자 확인은 기존 자동화 사용 중이라는 사실까지다.
- 운영 적용: 기존 자동화 사용 중 (사용자 확인). 에이전트 미적용.
- 복구: 로컬 보관 작업은 운영 서버를 바꾸지 않았다. 운영 자동화를 변경할 때는 서버의 현재 설정과 백업을 확인한 뒤 되돌린다.
