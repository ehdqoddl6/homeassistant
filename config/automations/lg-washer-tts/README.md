# LG 세탁기 TTS 알림

예상 완료 시각 30분·20분·10분 전 알림과 완료 알림을 **하나의 자동화**로 거실 스피커에서 안내한다.
2026-10-04 사용자가 기존 10분 전 알림 테스트 성공을 확인했다. 통합 자동화의 실제 동작은 아직 확인하지 않았다.

## 파일과 상태

| 파일 | 용도 | 상태 |
| --- | --- | --- |
| [automation.yaml](automation.yaml) | 예상 완료 30분·20분·10분 전과 완료 알림을 한 자동화로 구성 | 로컬 수정·정적 검증 완료, 운영 미적용. 기존 10분 전만 사용자 테스트 성공 |
| [history/2026-11-01-before-merge-completed.yaml](history/2026-11-01-before-merge-completed.yaml) | 사용자 제공 기존 완료 자동화 | 비교·복구용 보관본, 운영 적용 대상 아님 |

## 적용 위치와 동작

`automation.yaml`은 UI의 **단일 자동화 YAML 편집기**에 넣는 매핑 형태다.
현재 저장소에는 이 파일들을 읽는 상위 include가 없으며, 서버 설정과 연결되어 있지 않다.
자동화 목록 파일이나 패키지에 그대로 include하는 용도가 아니다.

사전 알림은 실제 남은 시간 센서가 완료 예정 날짜·시각을 나타내는 `device_class: timestamp`일 때 사용할 수 있다.
기존 10분 전 설정은 사용자가 테스트 성공을 확인했다. 새 YAML은 **기존 10분 전 자동화 한 개를 교체**하는 용도다. 기존 완료 자동화는 비활성화해야 완료 알림이 중복되지 않는다. 30분·20분 전 자동화도 따로 만들지 않는다.
센서가 숫자나 기간 문자열이면 해당 형식에 맞는 다른 트리거가 필요하다.

세 개의 `time` 트리거는 센서의 예정 시각보다 각각 30분·20분·10분 먼저 실행한다. 각 트리거의 `id`가 TTS 문구의 분 수로 들어간다. `event.setaggi_notification` 상태 변경은 네 번째 트리거로 사용하며 기존 완료 안내 문구를 재생한다.
예정 시각이 조정되면 실제 완료까지 남은 시간과 차이가 생길 수 있다.
알림 후 예정 시각이 다시 늦춰지면 재알림할 수 있으며, `mode: single`은 세탁 1회당 알림 1회를 보장하지 않는다.
트리거 시각에 Home Assistant가 정지되어 있거나 예정 시각 갱신으로 트리거 시각이 이미 지나면 알림을 놓칠 수 있다.

완료 트리거는 기존과 동일하게 이벤트 종류를 구분하지 않는 상태 트리거다. 사용자가 세탁기는 한 대라고 확인했다. 같은 세탁기에서 완료 외 알림도 이 이벤트 엔티티에 기록되는지는 미확인이다.

## 검증과 운영 적용

- 2026-10-04 로컬 YAML 2개의 문법·중복 키·단일 자동화 구조와 문서 상대 링크 24개를 검증했다.
- 2026-11-01 사전 알림 YAML의 세 트리거·ID·TTS 템플릿을 정적으로 확인했다. 이어 기존 완료 상태 트리거를 네 번째로 합치고 TTS 분기와 보관본을 정적으로 확인했다. 통합 자동화의 실제 트리거와 음성 출력은 미검증이다.
- Home Assistant 구성 검사, 에이전트의 실제 세탁·TTS 동작 검증: 미실행.
- 사용자 확인: 2026-10-04 “10분전 알람 테스트성공했어”. 실제 시간 트리거 검증인지 액션 수동 실행인지는 미확인이다.
- 사용자 설정 확인: 같은 날 “예제로 준거 맞아”라고 알려 제공한 YAML을 사용 중인 설정으로 기록했다.
- 에이전트의 서버 적용·재로드·재시작: 미실행.
- 이번 통합을 되돌릴 때는 Git의 작업 전 `before-complete-10min.yaml`을 10분 전 자동화에 복원하고, 보관한 `history/2026-11-01-before-merge-completed.yaml`로 완료 자동화를 다시 활성화한다.
