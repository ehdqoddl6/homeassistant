# 날씨 알려줘

필요할 때 호출하면 기존 아침 브리핑의 날씨 센서를 읽고 Gemini로 원고를 생성해 거실 스피커로 재생한다.
사용자가 제공한 `잠실가는 버스 알려줘` 스크립트의 AI 생성·재시도·TTS 흐름을 따른다.

## 파일과 적용

- [script.yaml](script.yaml): UI의 **단일 스크립트 YAML 편집기**에 붙여 넣는 매핑이다. 자동화용 YAML이 아니다.
- Home Assistant의 설정 → 자동화 및 장면 → 스크립트에서 새 스크립트를 만들고 YAML 편집기에 내용을 넣는다.
- 최상위 `script:` 또는 `weather_briefing:`으로 감싸지 않는다. `scripts.yaml`에 직접 넣는 경우에는 별도의 스크립트 키가 필요하므로 이 파일 전체를 그대로 덮어쓰지 않는다.
- 저장소는 실제 서버와 연결되어 있지 않고 이 파일을 읽는 상위 include도 없다.
- 자동 실행 시각·요일·트리거는 없다. 기존 버스 질의가 스크립트로 연결되는 방식에 맞춰 새 스크립트를 음성 호출 대상으로 연결한다. 실제 Assist 노출·질의 라우팅은 미확인이다.

## 입력과 출력

| 항목 | 근거 |
| --- | --- |
| 날씨 센서 15개 | 기존 [아침 브리핑 YAML](../../automations/morning-briefing/automation.yaml)의 `sensor.naver_weather_hopyeongdong_nalssi_*` 엔티티 재사용. 정확한 ID는 스크립트에 명시 |
| `ai_task.google_ai_task` | 기존 아침 브리핑과 사용자 제공 버스 스크립트 |
| `tts.google_ai_tts` | 기존 아침 브리핑과 사용자 제공 버스 스크립트 |
| `media_player.geosil`, 음성 `Leda` | 기존 아침 브리핑과 사용자 제공 버스 스크립트 |

현재 날씨·기온·체감온도·최저/최고기온·강수확률·습도·먼지 상태를 자연스러운 반말로 안내한다.
센서의 빈 값이나 `unknown`·`unavailable`은 추측하거나 0으로 바꾸지 않도록 지시한다.
센서 갱신 시각·현재 가용성·단위는 서버에서 확인하지 않았으며, 단위는 기존 YAML의 표기를 따른다.

AI 생성은 최대 3회 시도하고 실패 사이에 2초를 기다린다. 재시도마다 응답 변수를 초기화한다.
비어 있지 않은 문자열 응답을 얻으면 TTS를 한 번 요청하고 종료한다. 모두 실패하면 고정 안내문을 재생한다.
TTS 오류는 AI 생성 재시도에 포함하지 않는다. `mode: single`은 스크립트 실행 중 중복 호출을 막지만,
스피커의 음성 재생 완료까지 대기하거나 다른 스크립트의 재생을 제어하지 않는다.

## 검증과 적용 상태

- 로컬 YAML 문법·중복 키·단일 스크립트 구조·재시도/TTS 구조 및 기존 엔티티 18개 재사용 여부: 정적 검사 통과.
- 문서 상대 링크 13개와 변경·추가 파일 5개의 공백 검사 통과. 기존 자동화 파일의 변경 없음 확인.
- Home Assistant 구성 검사·Jinja 렌더링·실제 AI 응답·TTS 청취·음성 호출 연결: 미검증.
- 운영 적용: 미적용. 기존 아침 브리핑과 버스 스크립트를 변경하지 않는다.
- 복구: 적용 후 필요 없으면 새 스크립트의 음성 호출 연결을 해제하고 해당 스크립트만 삭제한다.
